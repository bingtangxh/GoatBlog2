# 当我试图使用实验室的老电脑：从集体蓝屏到 XP 病毒考古

最近因为 FPGA 课设，我需要在学校实验室里使用一批比较老的台式机。

这些电脑是 Dell OptiPlex 330。根据网上资料，这一型号大约是 2008 年前后的产品。如今它们已经算得上相当有年代感了。

实验室里的电脑平时并没有得到什么特别精细的维护。电源线、键盘、鼠标、VGA 线等各种线缆散落在桌子下面，我于是先把自己位置上的设备重新接好，准备开机。

然后，我得到了第一份惊喜：

**蓝屏。**

而且是 Windows XP 时代非常经典的：

```text
STOP: 0x0000007B
```

## 一、为什么实验室里的电脑全都蓝屏？

0x7B 通常与启动阶段无法访问系统盘有关，因此我首先想到的是硬盘或者磁盘控制器的问题。

我先尝试了安全模式。

还是 0x7B。

再试“最后一次正确的配置”。

还是 0x7B。

于是我换了一台同实验室的电脑。

蓝屏。

第三台。

还是蓝屏。

这时候就有点绷不住了。

难道这个实验室里的电脑全坏了？

我甚至开始认真思考一种非常离谱的可能性：

> 会不会这个实验室以前发生过某种特殊的声学事件，把所有机械硬盘的盘片都激发出了完全相同的共振，然后这些硬盘恰好全部以同一种方式损坏？

当然，这基本属于科幻小说情节。

另一个可能是，这些电脑从被放进实验室的第一天起就是坏的，只不过因为机箱和显示器上都贴着学校的固定资产标签，所以它们就这样一直躺在这里，几十年间也没人处理。

毕竟固定资产一旦进入学校管理体系，移动、报废、拍卖等操作往往都涉及额外的流程。

不过很快，我们发现了真正的原因。

## 二、原来不是硬盘，是 BIOS

我的同学比我更早想到检查 BIOS。

进入 BIOS 设置之后，他发现 SATA 控制器模式被设置成了：

```text
AHCI
```

于是尝试改成：

```text
ATA
```

保存，退出，重启。

**XP 正常启动了。**

这一下基本就把问题解释通了。

这些电脑开机时实际上还会提示：

> CMOS 电池电压过低，请按 F1 继续。

也就是说，主板上的纽扣电池已经没电，导致 CMOS 中保存的 BIOS 配置无法正常保持。

原本 Windows XP 是按照 ATA/兼容模式安装和配置的；而 BIOS 设置丢失后，机器恢复成了默认的 AHCI 模式。

于是：

```text
CMOS 电池没电
        ↓
BIOS 设置丢失
        ↓
SATA 模式恢复为 AHCI
        ↓
XP 启动时无法使用预期的磁盘控制器
        ↓
STOP 0x0000007B
```

这也解释了为什么实验室里的多台电脑会出现完全相同的故障。

不是它们的硬盘集体在同一天死亡了。

而是它们作为同一批大约十几年前的电脑，使用着同样老化的 CMOS 电池，于是出现了相同的问题。

至此，第一个谜题解决。

然而我很快发现：

**这台电脑还有第二个问题。**

## 三、XP 能启动了，但磁盘打不开

修改 BIOS 设置之后，我这台电脑终于能够进入 Windows XP。

我打开“我的电脑”。

然后发现：

**所有本地磁盘都打不开。**

双击没有反应。

右键 → 打开，没有反应。

右键 → 资源管理器，也没有反应。

鼠标指针甚至会短暂出现一下类似程序启动时的状态，然后什么都没有发生。

这个现象让我立刻想到了一种非常经典的 Windows 老病毒行为。

我打开 CMD。

执行：

```bat
dir C:\ /a-d
```

这里 `/a-d` 的意思是显示文件，而不管它是否具有隐藏、系统等属性。

然后我看到了：

```text
C:\autorun.inf
```

于是直接：

```bat
notepad C:\autorun.inf
```

打开它。

内容非常简单：

```ini
Open=SafeSys.exe
```

这下基本就很有意思了。

## 四、这不是光盘，为什么硬盘里会有 autorun.inf？

`autorun.inf` 本身并不是病毒。

它在 Windows 的历史上有很多合法用途，尤其是光盘自动运行、可移动介质等场景。

但是现在的情况非常可疑：

* 这是本地硬盘；
* 每一个分区都无法正常双击打开；
* 每个分区似乎都存在类似的自动运行行为；
* `autorun.inf` 中明确指定了一个 EXE；
* 这个 EXE 的名字还是 `SafeSys.exe`；
* 打开 `autorun.inf` 的过程中，记事本还会莫名其妙被关闭。

而如果我打开的是其他普通文件，Notepad 并不会被关闭。

这就已经不像是普通的系统配置问题了。

更像是：

> 有一个正在后台运行的恶意程序，正在监视与自己有关的操作。

尤其是：

```ini
Open=SafeSys.exe
```

这意味着用户以为自己是在打开磁盘，实际上可能是在触发另一个程序。

这也是许多 Windows XP 时代恶意软件常见的传播思路：

```text
用户双击磁盘
       ↓
Shell 处理 autorun.inf
       ↓
执行恶意程序
       ↓
感染当前系统
       ↓
向其他分区/可移动介质写入文件
       ↓
用户继续使用 U 盘
       ↓
感染下一台电脑
```

于是事情开始从“老电脑维修”变成了“XP 病毒考古”。

## 五、这东西甚至会主动对付杀毒软件

继续调查之后，我们还发现，这个恶意软件并不只是简单地留了一个 `autorun.inf`。

它还存在一些非常典型的对抗行为。

例如，它会按照窗口标题栏匹配窗口，然后自动关闭特定程序。

也就是说，如果它发现某个窗口标题符合自己的目标，就会尝试把窗口关掉。

这意味着它可以针对某些工具进行干扰。

更有意思的是，它还使用了映像劫持一类的机制，导致当时一些主流杀毒软件无法正常启动。

于是整个行为链就变成了：

```text
感染系统
   ↓
修改系统行为
   ↓
阻止/关闭安全软件
   ↓
隐藏自身
   ↓
通过 autorun.inf 传播
   ↓
维持常驻
```

这已经非常符合那个年代恶意软件的典型风格。

今天看来，这些手段并不算多么先进。

但放在 Windows XP 时代，它们非常实用。

而更有意思的是，我们现在看到的并不是一份病毒样本分析报告，而是一台实验室里不知道已经放了多少年的真实电脑。

它很可能就这样沉睡了很多年。

## 六、最后发现：病毒本身也很“XP”

后来，我们确认恶意程序实际上是借助 `svchost.exe` 运行的。

而且同时存在两个相关的 `svchost.exe` 进程。

如果只结束其中一个：

```text
svchost.exe #1
```

另一个：

```text
svchost.exe #2
```

就会立即把它重新启动。

反过来也类似。

也就是说，这两个进程之间形成了某种互相维持的关系。

因此单独结束一个进程没有意义。

真正有用的方法是：

**同时结束两个相关进程。**

后来我的舍友找到了一个更加直接的办法。

他使用 Windows XP 时代的 `ntsd` 命令，根据进程 PID 一次性结束了两个相关进程。

结果：

**两个进程同时消失。**

而且这一次没有任何一个进程再把另一个重新拉起来。

病毒的常驻进程就这样被暂时干掉了。

遗憾的是，我们当时没有把具体的 PID 查询过程完整记录下来，因此现在已经无法还原当时究竟是通过什么方式准确识别出这两个恶意 `svchost.exe` 的。

这也是这次排查中比较可惜的一点。

如果当时留下：

```text
tasklist /svc
sc queryex
```

之类的完整输出，那么现在就可以非常明确地把：

```text
svchost.exe
    ↓
PID
    ↓
服务
    ↓
恶意 DLL / 服务配置
```

完整对应起来。

## 七、从“坏电脑”到“时间胶囊”

回头看，这几台 OptiPlex 330 的问题其实非常有意思。

最开始，我看到的是：

> **三台电脑全部 0x7B 蓝屏。**

这很容易让人产生“硬件是不是全坏了”的感觉。

但真正原因却是：

> **一批老电脑的 CMOS 电池同时进入了寿命末期。**

BIOS 配置丢失，又导致 XP 使用了错误的磁盘控制器模式。

解决 BIOS 设置以后，电脑终于启动。

然后又发现：

> **电脑里还躺着一套 Windows XP 时代的恶意软件。**

这个恶意软件甚至还保留着那个时代非常典型的行为：

* `autorun.inf`；
* 可疑 EXE；
* 窗口标题匹配；
* 主动关闭程序；
* 映像劫持；
* 利用 `svchost.exe` 常驻；
* 两个进程互相维持；
* 针对杀毒软件进行干扰。

于是这台电脑突然变得非常像一个数字考古现场。

它不只是“一台旧电脑”。

它保存的是一个过去的计算环境：

```text
Windows XP
旧版 BIOS
老式 SATA 兼容模式
旧软件
旧病毒
旧式恶意软件传播方式
旧式杀毒软件
以及十几年前留下来的系统配置
```

我们本来只是想拿它做 FPGA 课设。

结果第一步：

> **修 BIOS。**

第二步：

> **查病毒。**

第三步：

> **研究 XP 时代恶意软件。**

最后甚至还得拿出 `ntsd` 这种今天已经很少有人会主动想到的工具。

这大概就是使用老机器最有意思的地方：

**你永远不知道一台看起来只是“放在实验室角落里的旧电脑”，里面究竟还保存着什么。**

它可能只是一个坏掉的固定资产。

也可能是一块已经被遗忘十几年的数字时间胶囊。
